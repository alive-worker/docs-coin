市场结构与流动性 / 步进

步进核验：打到目标价按吃进量进一，没打到按剩余量扣除

SwapMath.computeSwapStep 在计算单步手续费时有两条根本不同的分支：打到价格目标时，手续费按实际吃进量乘以费率除以 1000000 减费率向上进一，多余输入留给下一步；未打到目标时，手续费等于剩余输入减去曲线吃进量，把本步输入全部耗尽。曲线要 998 时打到需付 1002，传入 1001 付不起 1002 只能走未打到分支，曲线吃进回落至 997。这些是 SwapMath.sol 与 UniswapV3Pool.sol 的整数推导规则，不构成投资建议。

核验清单

  • ✓SwapMath.computeSwapStep 中，价格是否打到 sqrtRatioTargetX96 决定了手续费分支的选择。
  • ✓打到目标价时（sqrtRatioNextX96 == sqrtRatioTargetX96），手续费由实际吃进量乘以费率再除以 1000000 - feePips 向上进一得到，未消耗的剩余代币保留给后续步骤。
  • ✓未打到目标价时（sqrtRatioNextX96 != sqrtRatioTargetX96），手续费直接等于 amountRemaining - amountIn，将当前步的输入代币完全耗尽。
  • ✓费率 3000、曲线吃进需 998 时打到目标需付 1002；若传入输入只有 1001，无法打满目标价，退化至先扣分支，曲线吃进骤降为 997，无法触发 cross 穿档更新。

1. 单步撮合的两条手续费支路

在 Uniswap V3 中，任何跨越区间的兑换都会被池子主循环拆分为若干个步进（Swap Step）。每一阶段的计算均委托给 SwapMath.computeSwapStep。在这个核心库中，手续费的计算存在两条截然相反的路径：

// SwapMath.sol
if (exactIn) {
    if (sqrtRatioNextX96 != sqrtRatioTargetX96) {
        // 未打到目标价格：手续费等于剩余全部输入减去曲线实际吃进的量
        feeAmount = uint256(amountRemaining) - amountIn;
    } else {
        // 打到了目标价格：手续费按吃进量重新向上进一核算
        feeAmount = FullMath.mulDivRoundingUp(amountIn, feePips, 1e6 - feePips);
    }
}

这个 if-else 分支是整个 Uniswap V3 离散流动性步进的核心分水岭：

  1. 打到目标价（Hit Target）：说明输入的代币量足够充裕，价格正好被推到了下一个已初始化的价格档位 tickNext。此时这一个 step 只需要扣除把价格推进到该目标点所需的代币，剩下的输入必须完整保留，交给循环的下一轮继续消耗；
  2. 未打到目标价（Miss Target）：说明输入的代币不足以穿透当前区间，兑换将在该价格步进内彻底结束。此时池子不会保留任何剩余代币，而是将传入的 amountRemaining 全部吞纳，扣除曲线吃进的 amountIn 之后，差额全部算作本步的手续费。

2. 打到目标价：吃进 998，手续费进一为 4

假定当前池子费率为 3000（0.3%），当前步骤的已初始化目标价格为 sqrtRatioTargetX96。根据流动性与价格差反推，曲线如果要正好推移到目标价格，需要吃进 amountIn = 998 代币。

此时假定调用者传入了一笔充裕的输入 amountRemaining = 5000。因为 5000 远大于推进到目标所需的数量，算法判定本步可以完美打到目标价（sqrtRatioNextX96 = sqrtRatioTargetX96）。

此时进入打到分支：手续费不看 5000，而是按 998 重新反算：

feeAmount = FullMath.mulDivRoundingUp(998, 3000, 1000000 - 3000)
          = FullMath.mulDivRoundingUp(998, 3000, 997000)

乘积为 998 * 3000 = 2994000。除以 997000：

2994000 / 997000 = 商 3，余数 3000

由于余数 3000 大于 0，mulDivRoundingUp 强制进位，手续费判定为 4。因此，本步为了打到目标价格，总共消耗的输入代币为：

totalStepIn = amountIn + feeAmount = 998 + 4 = 1002

初始传入的 5000 减去消耗的 1002，剩余的 3998 完整传递到下一个循环步，池子同时触发 cross 穿档更新流动性。

3. 传入 1001：付不起 1002 只能走未打到分支

现在观察极具启发性的边界测试：假定曲线打到目标依然需要 998，但调用者传入的 amountRemaining 恰好是 1001。

在没有深入阅读合约源码的工程师眼中，1001 已经大于 998，似乎足以推进到目标点。然而在 computeSwapStep 内部，精确输入判定能否打到目标时，首先将 1001 扣除 0.3% 手续费送入曲线：

amountRemainingLessFee = 1001 * 997000 / 1000000 = 997997000 / 1000000 = 997

1001 扣完手续费后，曲线只能吃进 997！而打到目标价需要 998。因为 997 < 998，算法判定：无法打到目标价格！

因为未打到目标价格，合约走向 else 分支：

amountIn = 997
feeAmount = amountRemaining - amountIn = 1001 - 997 = 4

此时，价格停留在未达目标价的中间位置（sqrtRatioNextX96 != sqrtRatioTargetX96），本步将 1001 完全耗尽，剩余代币变为 0，整个交易循环终止！池子绝不会触发穿档更新流动性！

4. 1 wei 差距导致穿档失败的连锁反应

从表格中可以看到，从 1002 到 1001，虽然输入只差了微不足道的 1 wei，但池子内部的执行状态发生了剧烈跳变：

  1. 曲线吃进量跳水：1002 让曲线吃进 998，而 1001 让曲线吃进跌落至 997，整整少了 1 个代币；
  2. 价格跳步终止：1002 能够让价格精确落到 step.tickNext，从而在池子循环中触发 ticks.cross(step.tickNext)，更新活跃流动性；而 1001 无法触达目标，价格停在距离档位仅差 1 步的边缘，流动性无法切换；
  3. 套利机器人状态失真：如果套利机器人按照连续实数模型预测，会认为 1001 已经进入下一个高流动性区间；但链上执行却把价格死死卡在前一个区间的最末端，导致后续预测滑点产生系统性偏差。

5. 单步手续费核验的标准化流程

在对链上兑换日志或离线模拟器进行核验时，必须遵循以下标准判定步骤：

  1. 首先读取当前步传入的 amountRemaining 与打到 sqrtRatioTargetX96 所需的 amountIn；
  2. 若为精确输入，先用 amountRemaining * (1e6 - feePips) / 1e6 向下取整计算可用净额；
  3. 若该净额小于目标 amountIn，则判定为未打满目标：曲线吃进量取该净额，手续费直接为 amountRemaining - netIn；
  4. 若该净额大于等于目标 amountIn，则判定为打满目标：曲线吃进量固定为目标 amountIn，手续费必须按 amountIn * feePips / (1e6 - feePips) 向上进位重新计算，扣除后的余额继续送入下一循环。

本文是分析框架。分支切换逻辑与进位除数来自 SwapMath.sol 与 UniswapV3Pool.sol v1.0.0。998、4、1002 与 997 是严格整数推导的核验结果，不构成投资建议。

6. 常见误读

为什么单步兑换手续费不能始终采用「输入乘以费率」？

因为跨步大单会被拆解为多个价格区间。如果某一步打到了下一个初始化的 tickNext，该步只需要消耗正好推进到该价格所需的代币，多余的输入必须完整结转给下一步。因此打到目标价时，手续费只能按该步曲线实际吃进的量单独特算；只有当输入不足以打到目标价、交易在该步彻底终结时，手续费才用剩余全部输入减去曲线吃进量。

打到目标价时，手续费除数为什么是 1000000 减费率而不是 1000000？

因为此时已知的基数是曲线实际吃进的净输入 amountIn，而不是包含手续费的总支付额。手续费是在这个净量外部叠加的，因此其计算公式为精确输出模式下的 FullMath.mulDivRoundingUp(amountIn, feePips, 1e6 - feePips)。

传入 1001 为什么不能让曲线吃进 998？

因为曲线吃进 998 时，998 乘以 3000 除以 997000 的商为 3、余数为 3000，手续费向上进一为 4，打满目标价必须支付 1002。传入 1001 无法支付 1002，判定为未打满目标；在未打满分支中，1001 先扣除手续费送入曲线，1001 乘以 997000 除以 1000000 向下取整只能得到 997。差 1 wei 导致曲线吃进骤减 1 wei，且无法触发穿档。

推广信息：精确拆解单步兑换手续费分支是构建高精度套利路由与状态模拟的必备功底，而日常现货兑换前端会将多步拆解过程封装在报价背后。若在研究之余需要测试小额现货兑换或多链资产交互，可自行查看 Allswap 兑换。该服务入口与 1002 还是 1001 的单步整数推演无关，亦不构成平台背书或投资建议。请合规使用链上工具，勿用于非法用途。
