档距核验：费率 3000 的间距是 60，最外一档也不是 -887272

Uniswap V3 把手续费档和 tick 间距分成两个字段，工厂合约不会用其中一个推算另一个。v1.0.0 构造函数写下的三对是 500 与 10、3000 与 60、10000 与 200。费率 3000 是输入金额的 3000/1000000，等于 0.003，也就是 0.3%；间距是 60 个 tick，不是 3000。TickMath 把 MIN_TICK 定为 -887272、MAX_TICK 定为 887272。checkTicks 放行这个绝对边界，flipTick 却要求 tick 能被间距整除，而且这条 require 没有错误字符串。-887272 对 60 的余数是 -52，所以 0.3% 池能挂上流动性的最低 tick 是 -887220，最高是 887220，两端各空出 52 档。沿用本站开方价那篇的截断，1.0001 的 52 次方切到小数点后 12 位是 1.005213282127。再往外一格、且能被 60 整除的 -887280，则因为小于 MIN_TICK，以 TLM 回退。负向压缩是另一处不对称：当前 tick 为 -59、间距为 60 时，向零截断得到 0，合约因余数不是 0 再减 1，压缩下标是 -1，起算 tick 是 -60。这些比值是教学换算，不是 2026 年 11 月 4 日某个池子的读数，也不构成投资建议。

  • ✓读工厂的 feeAmountTickSpacing(3000)，或读池子的 tickSpacing。期待 60。读到 3000，就不是 v1.0.0 构造函数创建的那一档。
  • ✓对 -887272 按间距取余。间距 60 的余数是 -52。可用下沿是 -887220，可用上沿是 887220。-887280 能被 60 整除，但会以 TLM 回退。
  • ✓52 档的价格比用 1.0001 的 52 次方，小数直接截断到 12 位，得到 1.005213282127。不要把 52 本身当成价格。
  • ✓tick 为 -59、间距为 60 时，向零截断是 0。余数非 0 且 tick 为负，压缩下标再减 1，得到 -1，起算 tick 是 -60。

1. 费率 3000 和间距 3000 写在两个槽里

UniswapV3Factory v1.0.0 的构造函数依次调用 enableFeeAmount(500, 10)、enableFeeAmount(3000, 60)、enableFeeAmount(10000, 200)。第一个参数是费率，单位是百万分之一。3000/1000000 = 0.003，也就是这笔输入的 0.3%。第二个参数是 tickSpacing，单位是 tick 的格数。60 不是 3000 的别名，两个数字只是碰巧出现在同一次调用的两个位置上。

enableFeeAmount 不计算 fee/50。它检查调用者是 owner，fee 小于 1000000，tickSpacing 大于 0 且小于 16384，并且这个 fee 的槽还是空的。3000 作为间距也能通过「小于 16384」这一条，所以单靠上界拦不住把费率抄进间距。构造函数没有把 3000 传进第二个参数，它传的是 60。槽一旦写成 60，再调用 enableFeeAmount(3000, 3000) 会因为槽非空而回退。写错的间距不能靠再调一次同一个函数盖掉。

500/50 = 10、3000/50 = 60、10000/50 = 200，这三对碰巧能整除。函数体里没有这道除法。把「间距等于费率除以 50」写成合约规则，只是对这三次调用的事后观察。本篇只核这三对构造参数。手续费最终进了谁的口袋，是手续费核验：池子上的费率，不等于流动性提供者留下的那一截那篇的问题。本篇只问页面上的 3000 到底是费率还是间距。

2. 绝对边界过得了 checkTicks，过不了整除

TickMath v1.0.0 把 MIN_TICK 定为 -887272，MAX_TICK 定为它的相反数 887272。checkTicks 有三条 require：下沿必须小于上沿，否则 TLU；下沿不得小于 MIN_TICK，否则 TLM；上沿不得大于 MAX_TICK，否则 TUM。-887272 作为下沿、887272 作为上沿，过得了这三关。只读 TickMath 的人会据此认为每个池子都能把全区间挂在这两档上。

过不了的是位图。TickBitmap v1.0.0 的 flipTick 在改位之前要求 tick % tickSpacing == 0。这条 require 没有错误字符串，失败时回退原因是空的。第一次把某个边界从零流动性写成非零，就会走进 flipTick。余数不是 0，这个边界不会被写进位图，仓位也打不开。已经初始化的 tick 都是从这条路走过来的，所以位图里不会留下一个不能被间距整除的边界。

-887272 对 60 取余。887272 = 60×14787 + 52，正余数是 52。余数的符号跟被除数走，所以 -887272 % 60 = -52，不是 8，也不是 0。最低可用 tick 要把这 52 档往回收，得到 -887220。-887220 大于等于 MIN_TICK，并且 -887220 % 60 = 0。再往外一格的对齐 tick 是 -887280。它能被 60 整除，但比 MIN_TICK 小 8，checkTicks 以 TLM 回退。两个相邻的失败不是同一种失败：-887272 死在整除，-887280 死在下界。上沿对称。887272 % 60 = 52，最高可用 tick 是 887220。887280 大于 MAX_TICK，回退码是 TUM。

间距 10 时，-887272 % 10 = -2，可用边界是 -887270 和 887270，缺口 2 档。间距 200 时，余数是 -72，可用边界是 -887200 和 887200，缺口 72 档。只有间距为 1 时余数才是 0，MIN_TICK 本身可用。v1.0.0 的构造函数没有启用间距 1。

3. 52 档的价格比是 1.005213282127

52 不是价格 52，也不是价格差 52。兑换核验：开一次方，不等于池子报价把单个 tick 的价格比写成 1.0001 的 tick 次方，小数直接截断到 12 位，不四舍五入。两个 tick 之间的价格比等于 1.0001 的 tick 差次方。-887220 比 -887272 高 52 档，价格比是 1.0001 的 52 次方，截断到 12 位是 1.005213282127。写成 1，等于说这两档价格相同。写成 52，等于把档数当成了价格。

同一截断下，间距 10 的 2 档缺口是 1.000200010000，间距 200 的 72 档缺口是 1.007225619743。缺口越大，这个费率档真正能挂到的全区间，就比 TickMath 的绝对全区间更窄。窄掉的是两端的价格比。中间那段流动性怎么换成代币数量，是仓位核验：仓位上的流动性，不等于代币余额的问题。边界如果过不了 flipTick，那篇的数量公式不会被调用。

4. 把间距写成 3000，一格的价格比会换一套

0.3% 池的一格是 60 个 tick，不是 3000 个。1.0001 的 60 次方截断到 12 位是 1.006017734268。1.0001 的 3000 次方是 1.349838561195。指数相差 2940，1.0001 的 2940 次方是 1.341764180903。用 3000 当作一格，一格的价格增幅是合约一格的 1.341764180903 倍。这不是多写了一个零就能解释的舍入，两格之间差了 2940 个 tick。

3000 小于 16384，所以上界检查拦不住这个抄写。拦住它的是构造函数实际传入的第二个参数，以及槽被占用后不能改写。核验时读池子的 tickSpacing，或者读工厂的 feeAmountTickSpacing(3000)，期待 60。读到 3000，说明这不是 v1.0.0 那次构造调用创建的档位，笔记不该再沿用 60 这张表。

5. 当前 tick 不必对齐，仓位边界必须对齐

initialize 把 sqrtPriceX96 交给 getTickAtSqrtRatio，再把返回的 tick 写进 slot0。这条路径没有对 tickSpacing 取余。因此一个 0.3% 池的 slot0.tick 可以落在不能被 60 整除的档上，包括开盘价刚好对应 MIN_TICK 的情形。页面上看到当前 tick 不能被 60 整除，不能当成池子坏了。

必须对齐的是仓位边界。mint 的下沿和上沿在第一次写入流动性时要能通过 flipTick。当前 tick 和边界 tick 是两个字段。用「必须整除」去拒绝当前 tick，会把合法开盘价判成故障。用「MIN_TICK 在每个费率档都是合法边界」去挂全区间，会在间距 60 的池子上得到空回退。先问读到的是 slot0.tick 还是仓位的 tickLower，再决定要不要取余。

6. 负 tick 不在格子上时，压缩下标再减 1

nextInitializedTickWithinOneWord 先算 tick / tickSpacing。Solidity 的整数除法向零截断。tick 为负且余数不是 0 时，结果再减 1，向负无穷靠一格。余数为 0 时不减。正 tick 也不减。这一格和时间加权核验：链上的平均 tick，不等于两端价格的平均数里的负数窗口是同一类不对称：只用正数做测试，看不出多出来的那一次减法。

教学数取 tick -59、间距 60。-59/60 向零是 0，余数是 -59。合约写下 -1。下标乘回间距，起算 tick 是 -60。只做向零截断会从 tick 0 起算。两条起算线相差 60 档，价格比就是 1.006017734268。函数接着还会在这个字里寻找已经初始化的位。起算线已经高了 60 档，后面找到的位不会把这 60 档补回来。

tick -60 能被 60 整除，向零截断已经是 -1，余数为 0，不再减，和下标 -1 重合。多减的条件是余数，不是符号本身。正的对照：tick 59、间距 60，59/60 向零是 0，余数 59，但 tick 不小于 0，下标保持 0，起算 tick 是 0。这一侧向零截断和合约一致。只拿 59 这种正 tick 做测试，会把 -59 那一次减 1 漏掉。

7. 先读间距，再对边界取余

错误句式是「费率 3000 表示间距 3000」，以及「每个池子都能把流动性挂在 -887272」。更可靠的句子是「feeAmountTickSpacing 里的第二个数；-887272 对这个数的余数；余数不为 0 时往区间内收到的那一档；往外一格的对齐 tick 触发的是 TLM 还是 TUM；读到的 tick 属于 slot0 还是仓位边界；负 tick 除不尽时压缩下标有没有再减 1」。教学换算里，0.3% 池的可用边界是 -887220 和 887220，52 档的价格比是 1.005213282127。间距若被写成 3000，一格的价格比是 1.349838561195，而不是 1.006017734268。tick -59、间距 60，起算 tick 是 -60。

本文是分析框架。三对默认参数、16384 的上界和槽不可改写来自 v1.0.0 的 UniswapV3Factory。MIN_TICK、MAX_TICK 来自同一标签的 TickMath。整除检查和负向压缩来自同一标签的 TickBitmap。1.005213282127、1.000200010000、1.007225619743、1.006017734268、1.349838561195 和 1.341764180903 是按 1.0001 的整数次方截断到 12 位得到的教学值，未对任何实时池子做实测，也不构成投资建议。

8. 常见误读

费率 3000 是不是表示 tick 间距为 3000？

不是。v1.0.0 构造函数写的是 enableFeeAmount(3000, 60)。3000/1000000 = 0.003，是手续费比例。间距是另一个参数，值为 60。函数不拿费率除以 50 来推导间距。这个费率槽写过后，不能再用同一次调用改成 3000。

0.3% 池子能不能把流动性挂在 tick -887272？

不能。-887272 对 60 的余数是 -52，不是 0。flipTick 要求 tick % tickSpacing == 0，这条 require 没有错误字符串。能用的最低 tick 是 -887220，最高是 887220。-887280 能被 60 整除，但小于 MIN_TICK，checkTicks 以 TLM 回退。

tick 为 -59、间距为 60 时，压缩下标是 0 吗？

不是。向零截断的 -59/60 是 0，余数是 -59。tick 为负且余数不为 0 时，合约再减 1，下标是 -1，乘回间距是 tick -60。留下 0 会从 tick 0 起算，比合约高 60 档，价格比 1.006017734268。

推广信息：若要自己准备少量代币，以便对照池子页面上的 tickSpacing 和一笔仓位的上下沿，可自行查看 Allswap 兑换 的报价、费用与限额。该入口与 -887272 能否被 60 整除无关，也不代表对平台服务作保证。任何兑换须用于真实、合规的研究支出，勿用于违法用途。
