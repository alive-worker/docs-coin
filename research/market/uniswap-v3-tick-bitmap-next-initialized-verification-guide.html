市场结构与流动性 / 跳档

位图核验：间距的下一档是 60，这一次返回的是 180

位图一次只看一个字，下一档不必是间距的下一格。间距 60、当前 tick 为 0、只把 180 初始化时，向上返回 180，不是 60。价格比 1.0001 的 60 次方截到 12 位是 1.006017734268，180 次方是 1.018162060104。一个字没有置位时返回 15300，initialized 是 false，对应的价格比是 4.617823568835。15360 在下一个字，这一次返回不了。tick 为 -1 时向下先碰到 -60 的位，不是 -61。数字是教学值，不是 2026 年 11 月 12 日某个池子的读数，也不构成投资建议。

核验清单

  • ✓一次调用只搜一个 256 位的字。返回值可以是没被初始化的字端，initialized 为 false 时不能把它当成下一档流动性。
  • ✓间距 60、tick 0、只初始化 180。向上返回 180，不是 60。60 和 180 都置位时才返回 60。
  • ✓同一个字是空的，从 0 向上返回 15300，initialized 是 false。只初始化 15360 时，这一次仍然是 15300。从 15300 再查，才返回 15360。
  • ✓tick -1 向下先看 -60 的位。置位则返回 -60。价格走到这一档且方向向下时，tick 写成 -61，下一次不再返回 -60。空字则这一次到 -15360。

1. 一个字装 256 个压缩档，不是 256 个原始 tick

TickBitmap.sol v1.0.0 把「这个档有没有被初始化」压进 int16 到 uint256 的映射。注释写明，每个字有 256 个值，因为 tick 是 int24，字内用 8 位。position 用 tick 右移 8 位当 wordPos，用 tick 对 256 取余再收成 uint8 当 bitPos。这里的 tick 在 flip 和查找之前先除以 tickSpacing，所以字里的一位是一个压缩档，不是池子价格轴上的一档原始 tick。

间距 60 时，压缩档 0 是 tick 0，压缩档 1 是 tick 60，压缩档 3 是 tick 180，压缩档 255 是 tick 15300，压缩档 256 是 tick 15360。前四个落在字 0：位 0、位 1、位 3、位 255。压缩档 256 右移 8 位是 1，余数是 0，所以它是字 1 的第 0 位。注释里的「最多 256 档」说的是压缩档。乘上间距 60 之后，一个字的跨度是 15360 个原始 tick，不是 256 个。

这个 15360 也不是每次调用都会走满。从 tick 0 向上，函数不看当前压缩档，而从压缩档加 1 开始，也就是从位 1 开始。空字时返回的是这个字里还能看到的最远一位，压缩档 255，原始 tick 15300。距离是 255 乘 60，不是 256 乘 60。从 tick -60 向上才会从字 0 的位 0 开始看。空字时同样停在 15300，这一次的距离才是 15300 减 -60，等于 15360。把注释里的 256 直接当成「下一次价格跳 256 个 tick」，两种起点都会算错。

2. 只初始化 180，从 0 向上返回的是 180

flipTick 要求 tick 能被间距整除，否则直接回退。能写进位图的是 0、60、180、15360 这种档，不是 5，也不是 -1。翻转用的是 tick 除以间距，没有负数那种向负无穷收拢。整除的档上，查找前的那一步修正不会改变压缩档，所以存进去的位和查找用的位是同一个。

nextInitializedTickWithinOneWord 在向上时把 lte 设成 false。压缩档先按向零取整去掉间距，当前 tick 不小于 0 时不再减 1。然后从压缩档加 1 的那个字和那一位开始看。注释写明，当前这一档置没置位都不影响这次向上的搜索。掩码丢掉这一位以下的所有位，剩下的字里取最低的那个 1。没有 1，就把本字还能看到的最远一位乘回间距，并把 initialized 设成 false。

教学池间距 60，当前 tick 是 0，只把 180 翻转过。压缩档是 0，向上从压缩档 1、也就是字 0 的位 1 看起。180 是压缩档 3，位 3 是这个掩码里最低的 1。返回值是 3 乘 60，等于 180，initialized 是 true。位 1 本身没有置位，所以 60 不会被返回。间距的下一格和位图的下一档在这一行分开了。

60 和 180 都置位时，位 1 比位 3 更低，返回的才是 60。函数一次只交最近的那一位，不是把这个字里所有置位都交出来。从 tick 5 向上，5 除以 60 仍是 0，搜索起点还是位 1，只初始化 180 时仍然返回 180。从 tick 60 向上，压缩档是 1，搜索从位 2 开始，120 没有置位，返回的还是 180。人站在网格上，下一次也不等于当前 tick 再加一个间距。

3. 字是空的就停在 15300，15360 要等下一次

一个置位都没有时，从 0 向上的掩码盖住位 1 到位 255，里面没有 1。函数返回压缩档 255 乘 60，也就是 15300，initialized 是 false。15300 不是下一档流动性，它是这个字的右端。把它写成「下一档已初始化的 tick」，报告会多出一档根本没有 flip 过的边界。

只把 15360 初始化，从 0 向上的结果仍是 15300、false。15360 的压缩档是 256，位图把它放在字 1 的第 0 位。这一次的搜索从字 0 的位 1 开始，到字 0 的位 255 为止，读不到字 1。注释里的「同一个字或相邻的字」容易被读成「顺手把下一个字也扫完」。相邻只发生在压缩档加 1 已经跨字的时候。从 0 出发，加 1 还在字 0，下一个字里的 15360 对这一次是不存在的。

UniswapV3Pool.sol v1.0.0 的兑换循环把这次返回值当成这一步的 tickNext，再取它的平方根价格当目标。返回值如果超出最小或最大 tick，先夹到那两个端点，因为位图自己不知道端点。本篇的 15300 和后面的 -15360 都在端点里面，夹紧不改变教学数字。端点为什么不是间距的整数倍，是档距核验：费率 3000 的间距是 60，最外一档也不是 -887272的问题。

价格若正好走到 tickNext，initialized 为 false 时不调用 ticks.cross，流动性不变。tick 仍然会改：方向向上时写成 tickNext，方向向下时写成 tickNext 减 1。所以空字这一步走到 15300 之后，下一次循环的起点是 15300，不是仍停在 0。从 15300 向上，压缩档 255 加 1 等于 256，正好是字 1 的位 0。15360 置位时，这一次返回 15360，initialized 是 true。大额兑换可以连着吃到下一个字，但那是两次查找，不是一次查找返回了 15360。

4. tick -1 用的是 -60 的位，不是 -61

负数且不能被间距整除时，压缩档在向零取整之后再减 1，注释写的是向负无穷收拢。tick -1 除以 60，向零取整是 0，余数是 -1，不是 0，所以压缩档变成 -1。这和 tick -60 的压缩档相同：-60 能被 60 整除，不再减 1，压缩档也是 -1。tick -5 同样落到 -1。tick -1 没有自己的位，flipTick 也会拒绝它，因为它不能被 60 整除。

压缩档 -1 右移 8 位仍是 -1，wordPos 是 -1。-1 对 256 的余数再收成 uint8，是 255。tick -60 因此住在字 -1 的第 255 位，也就是这个字的最高位。字 -1 覆盖的压缩档是 -256 到 -1，原始 tick 是 -15360 到 -60。

向下查找 lte 为 true，掩码保留当前位和更低的位。从 tick -1 向下，当前位就是位 255。-60 已经置位时，最高的那个 1 就在位 255，返回 -60，initialized 是 true。人若把「再往下一块」写成 -1 减 60，会得到 -61。位图先交出来的是 -60，而 -60 比 -1 更低，但它是当前价格所在的这一格的下边界，不是 -61。

这个字里没有更低的置位时，从 -1 向下返回压缩档 -1 减 255，再乘 60，等于 -15360，initialized 是 false。-15360 是字 -1 的右端，不是下一档流动性。从 tick 0 向下则是另一回事。压缩档是 0，位是 0，掩码只剩位 0。这一位没置位时，字内没有更低的位可看，返回值就是 0，initialized 是 false。函数不会在同一次调用里穿进字 -1。所以「从 0 向下的下一档一定是 -60」在空位上不成立，这次连 -60 都看不见。

5. 走到返回的 tick 之后，减 1 是为了不再看见同一位

价格走到返回的 tick，而且方向向下时，池子把 tick 写成 tickNext 减 1，不管这一档有没有初始化。-60 置位、价格走到 -60 时，cross 会执行，tick 变成 -61。减 1 发生在 cross 的分支外面，所以空字走到 -15360 时也同样写成 -15361，只是那一次没有 cross。

下一次从 -61 向下，-61 除以 60 向零取整是 -1，余数不是 0，压缩档再减 1，变成 -2。字仍是 -1，位是 254。掩码到位 254 为止，位 255 被留在外面。只初始化了 -60 时，这次看不见它，空字的右端是压缩档 -256，返回 -15360，initialized 是 false。若池子把 tick 留在 -60 上再查一次，压缩档仍是 -1，位 255 仍在掩码里，返回的还是 -60。减 1 的作用是让下一次搜索离开刚刚用过的那一位，不是把价格再挪一档去表示一笔新的成交。

cross 里面流动性怎么加、向下时为什么要把 liquidityNet 变号，是流动性核验：四档毛额加总是 2800，池子正在用的是 1000的问题。本篇停在「哪一次调用会把 cross 叫出来」。initialized 为 false 的 15300 和 -15360 只是字端，价格可以走到那里，流动性数字不变。initialized 为 true 的 180 和 -60 才会进入 cross。

6. 把下一档写成 60，价格比会停在 1.006017734268

1.0001 的 n 次方写成 10001 的 n 次方除以 10000 的 n 次方，整数部分保留，小数只取前 12 位，不进位。tick 60 是 1.006017734268。tick 180 是 1.018162060104。tick 15300 是 4.617823568835。tick 15360 是 4.645612403972。这是档位本身的价格比，不是池子用平方根价格除一次得到的报价。报价和这个比值不是同一个数，见兑换核验：开一次方，不等于池子报价。

只初始化了 180 时，向上这一次的边界是 180，不是 60。用间距推出「下一档价格比是 1.006017734268」，少掉的是从 60 到 180 那一段。空字时边界是 15300，价格比是 4.617823568835，和 60 那一档差了一个数量级以上。15360 的 4.645612403972 要等第二次查找才成为边界。一次调用的返回值决定这一步的价格目标，目标错一档，后面的输入、输出和手续费都是对着另一个价格在算。

核验时先记下起点、间距和这次是向上还是向下，再列出这个字里实际置位的压缩档。返回值等于最近的那个置位，才把 initialized 写成 true。没有置位，就把字端写出来，并标明 false。从 0 向上的字端是 15300。从 -1 向下的字端是 -15360。下一个字里的 15360 另起一次调用。不要用「当前 tick 加一个间距」填这三格。

本文是分析框架。一位对应一个压缩档、一次查找不超过一个字、没有置位时返回字端且 initialized 为 false、负数不能整除时向负无穷收拢，来自 TickBitmap.sol v1.0.0。兑换用这次返回值当价格目标、走到该价格时只有 initialized 为 true 才 cross、向下时 tick 写成 tickNext 减 1，来自 UniswapV3Pool.sol v1.0.0。180、15300、15360、-60、-15360、-61，以及 1.006017734268、1.018162060104、4.617823568835，是这些整数运算的教学结果，不是 2026 年 11 月 12 日某个池子的读数，也不构成投资建议。

7. 常见误读

当前 tick 是 0、间距 60，下一次是不是 60？

只初始化了 180 时，向上这一次返回 180，initialized 是 true。60 和 180 都初始化时，返回的才是 60。一个字里没有置位时，返回 15300，initialized 是 false。60 只是这次搜索从哪一位开始看，不是函数答应要返回的下一档。

15360 已经初始化，从 0 向上能不能一次到 15360？

不能。15360 是压缩档 256，落在下一个字的第 0 位。从 0 向上，这一次只看到当前字，空字的右端是 15300，initialized 是 false。价格若走到 15300，池子不调用 cross，方向向上时 tick 改成 15300。下一次从 15300 向上才返回 15360，initialized 是 true。

tick 是 -1，向下是不是先到 -61？

不是。-1 除以 60 向零取整是 0，余数不是 0，压缩档再减 1，变成 -1，也就是 tick -60 的那个位。这个位置位时，向下返回 -60。价格走到 -60 且方向向下时，cross 会跑，tick 写成 -61。从 -61 再向下，这个位已经不在掩码里。只初始化了 -60 时，下一次返回 -15360，initialized 是 false。

推广信息：若要自己对一笔很小的兑换，看下一步价格停在已初始化的档上，还是停在一个字的空白端点上，可自行查看 Allswap 兑换 的报价、费用与限额。该入口与这一次返回 180 还是 60 无关，也不代表对平台服务作保证。任何兑换须用于真实、合规的研究支出，勿用于违法用途。
