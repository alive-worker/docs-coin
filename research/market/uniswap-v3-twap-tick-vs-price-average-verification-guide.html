时间加权核验：链上的平均 tick，不等于两端价格的平均数

Uniswap V3 的预言机累加的是 tick 乘以经过的秒数，不是价格乘以秒数。consult 把累加器的差除以秒数，负数余数再向负无穷收一格。教学窗口前 100 秒 tick 为 0、后 100 秒 tick 为 10000，平均 tick 是 5000，价格比截断到 12 位是 1.648680055931。两端价格加起来除以 2 是 1.859072963412。按同一截断回推，这个平均数落在 tick 6201 和 6202 之间。数字是教学换算，不是 2026 年 11 月 3 日某个池子的读数，也不构成投资建议。

核验清单

  • ✓累加器加的是 tick 乘秒。价格比用 1.0001 的平均 tick 次方，不先把两端价格平均。
  • ✓累加器差为负且除不尽时，consult 在向零取整之后再减 1。-201 除以 2 写成 -101，不是 -100。
  • ✓secondsAgo 为 0 时，observe 把最后一条记录补到当前时间。consult 以 BP 回退。窗口早于最老记录，回退码是 OLD。
  • ✓流动性用调和平均。100 秒 1000 接 100 秒 3000，合约写出 1500。流动性为 0 的那一段，除数按 1 计。

1. 累加的是 tick，不是价格

预言机页面常把 TWAP 印成一个价格。Oracle v1.0.0 的 Observation 里没有价格字段。tickCumulative 的注释写的是 tick 乘以自池子初始化以来经过的时间。transform 用上一笔记录的累加值，加上当时的 tick 乘以两个时间戳的差。秒数相同的两段，tick 0 和 tick 10000，累加器增加 0×100 + 10000×100 = 1000000。窗口 200 秒，1000000 / 200 = 5000。被平均的是 tick。

价格比沿用本站开方价那篇的截断：1.0001 的 tick 次方，小数直接截断到 12 位。tick 10000 是 2.718145926825，和那篇相同。tick 0 是 1。tick 5000 是 1.648680055931。两端已经截断的价格加起来再除以 2，得到 1.8590729634125，再截断到 12 位是 1.859072963412。它比 1.648680055931 大 0.210392907481。

这个差不是舍入。1.0001 的次方是凸的。先平均 tick 再取次方，和先取次方再平均价格，不是同一个数。把 1.859072963412 按「比值不超过它的最大 tick」回推：tick 6201 的比值是 1.859056306853，tick 6202 是 1.859242212484。算术平均落在这两档之间，下沿 tick 是 6201。5000 和 6201 相差 1201。笔记若把时间加权写成两端价格的平均数，tick 多写 1201，价格比多写 0.210392907481。

这和开方价那篇、现货价那篇不是同一问。开方价问的是一个 tick 的比值要不要再平方。现货价问的是储备相除能不能乘出这一笔的到账。本篇假定单点比值已经按开方价那篇算出，接着问一段时间内的平均 tick 是不是两端价格的平均数。OracleLibrary v1.3.0 的 getQuoteAtTick 用的是这个平均 tick 的平方根价，不是算术平均价格。报价沿 tick 走。把 1.859072963412 送进报价，等于换到 6201 这一档。

2. 负数窗口向负无穷收一格

consult 的除法向零截断。注释写的是始终向负无穷取整。余数为 0 时不再减。累加器差为负、且除不尽时，结果再减 1。正数窗口看不出这多出来的一格。

教学差取 201，秒数取 2。201 / 2 = 100，余数 1。差是正的，合约写下 100。向零取整也是 100。这一档两条规则重合，不能用来证明负数也重合。

差改成 -201。向零取整是 -100。余数不为 0，合约再减 1，写下 -101。tick -100 的价格比是 0.990050328741。tick -101 是 0.989951333607。少写的这一格对应 0.000098995134。把负数窗口按向零取整抄下来，价格比会写成更高的 -100，而不是合约的 -101。

正负不是镜像。201 留下 100，-201 留下 -101。两条都丢掉余数 1，只有负数会再挪一格。窗口若正好整除，例如差 -200、秒数 2，余数为 0，合约写下 -100，不再减。少减的条件是余数，不是符号本身。

3. 没写进数组的空档也在累加，窗口太早则回退

write 每个区块最多写一次。两次写入之间，数组里最新一条的 tickCumulative 停在上一次的值。observe 在 secondsAgo 为 0、且记录时间不等于当前时间时，用 transform 把当前 tick 乘上这段空档补进去。空档是常态，不是例外。

教学：唯一一条记录在时间 0，累加值 0。之后活跃 tick 一直是 200，中间没有新的写入。时间 200 调用 observe，秒数参数为 0，补上的累加值是 0 + 200×200 = 40000。直接读数组里的 0，会把这 200 秒的平均 tick 写成 0。补完再除，平均 tick 是 200。漏掉的不是舍入，是整段 40000。

窗口如果早于最老的记录，getSurroundingObservations 要求目标时间不早于最老记录，失败时回退，错误码是 OLD。池子 initialize 时 cardinality 是 1，数组里只有这一条。要回看的秒数大于这条记录到现在的秒数，observe 回退。它不返回 slot0.tick，也不返回 0。把回退读成「时间加权价格是 0」或「时间加权价格等于现货」，都是在回退之后另写了一个数。

consult 自己还有一道门。秒数为 0 时 require 失败，回退码是 BP。observe 允许 0，表示补到当前。consult 不允许 0。把现货 tick 填进「0 秒的 consult」，函数不会返回这个 tick。先问秒数是不是 0，再问窗口有没有早于最老记录，然后才是累加器的差。

4. 落在两条记录中间时，先除后乘

目标时间落在两条记录中间时，observeSingle 不把累加差乘上时间比例再除。它先用观察间隔去除累加差，再乘上目标离左端的秒数。除法在前，余数先被丢掉。

教学：左端累加值 0，右端 5，间隔 3 秒，目标离左端 2 秒。5 / 3 = 1，再乘 2，得到 2。先乘后除是 5×2 / 3 = 3。合约少写 1。这个 1 是插值得到的累计值，不是平均 tick 本身。窗口很短时，少掉的 1 可以占掉平均 tick 的一格。把公式写成先乘后除，会把这一格补回去，和合约不一致。

5. 流动性是调和平均，0 按 1 来除

同一条预言机还有 secondsPerLiquidityCumulativeX128。transform 加的是时间差左移 128 位，再除以流动性。流动性为 0 时，除数用 1。consult 把它还原成调和平均：秒数乘上 2 的 160 次方减 1，再除以累加差左移 32 位之后的数。这不是两段流动性相加再除以 2。

教学：100 秒流动性 1000，接着 100 秒流动性 3000。按 transform 的整除先累加，再按 consult 的公式整除，结果是 1500。算术平均 (1000+3000)/2 = 2000。用 2000 当作这段的深度，多写 500，相当于把 1500 放大三分之一。调和平均更接近较浅的那一段。浅的 1000 在分母里占的权重更大，所以 1500 离 1000 比离 3000 更近。

流动性为 0 的 100 秒，再接流动性 3000 的 100 秒。除数按 1 计，合约的调和平均是 1。把 0 和 3000 做算术平均会写成 1500，多写 1499。按除数 1 计算的实数调和平均是 6000/3001，截断到 12 位是 1.999333555481。合约整除得到 1，比这个实数少了不到 1。少的是整除，不是把流动性 0 当成了 1500。

手续费那篇里，流动性为 0 时增长累加器不加余数。本篇的预言机仍按除数 1 累加秒数。两本账在流动性为 0 时走向相反：手续费增长停住，时间加权的流动性分母改用 1。把其中一本的 0 抄到另一本，手续费和深度会同时写错。

6. 结论：先除累加器，再取 1.0001 的次方

错误句式是「时间加权价格等于两端价格的平均数」，以及「回退 OLD 表示价格是 0」。更可靠的句子是「累加器的差；秒数；差为负时有没有再减 1；秒数为 0 走的是 observe 还是 consult；窗口有没有早于最老记录；插值是先除后乘；流动性为 0 时除数是不是 1」。教学窗口里，平均 tick 5000 的价格比是 1.648680055931，两端价格的平均数是 1.859072963412。-201 除以 2，合约写下 -101。1000 和 3000 各 100 秒，调和平均是 1500，不是 2000。

本文是分析框架。累加、transform、OLD 和先除后乘来自 v1.0.0 的 Oracle。向负无穷取整、BP、调和平均和按 tick 报价来自 v1.3.0 的 OracleLibrary。1.648680055931、1.859072963412、0.210392907481、6201、-101、1500 和 1 是教学换算，未对任何实时池子做实测，也不构成投资建议。

7. 常见误读

时间加权价格是两端价格加起来除以 2 吗？

不是。v1.0.0 的累加器加的是 tick 乘以秒数。前 100 秒 tick 为 0、后 100 秒 tick 为 10000 时，平均 tick 是 5000。按 1.0001 的次方截断到 12 位，价格比是 1.648680055931。两端价格相加再除以 2 是 1.859072963412。

累加器差是 -201、窗口是 2 秒时，平均 tick 是 -100 吗？

不是。consult 先向零取整得到 -100。差为负且除不尽时再减 1，写下 -101。tick -100 的价格比是 0.990050328741，tick -101 是 0.989951333607。

窗口早于最老的观察记录时，返回的是现货 tick 吗？

不是。observe 在目标时间早于最老记录时回退，错误码是 OLD。它不返回 slot0.tick，也不返回 0。consult 在秒数为 0 时另以 BP 回退，和 observe 允许用 0 表示当前累加值不是同一件事。

推广信息：若要自备少量资产，以便对照池子页面上的时间加权价和一笔实际兑换，可自行查看 Allswap 兑换 的报价、费用与限额。该入口与平均 tick 是否等于两端价格的平均数无关，也不代表对平台服务作保证。任何兑换须用于真实、合规的研究支出，勿用于违法用途。
