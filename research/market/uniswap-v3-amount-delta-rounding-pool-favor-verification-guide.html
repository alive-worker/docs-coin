市场结构与流动性 / 进位

进位核验：同一价格区间收进要付 1，吐出只给 0

Uniswap V3 计算代币变化量时严格偏向池子：收进时向上取整多要 1，吐出时向下截断少给 1。在流动性 1000、价格 100 变到 101 的区间中，理论代币量为 0.099。池子向调用者收款时必须付 1；向调用者付款时只给 0。进位不对称性在相同区间产生 1 wei 剪刀差，彻底封堵舍入抽水攻击。这些是 SqrtPriceMath 与 FullMath 的整数截断规则，不构成投资建议。

核验清单

  • ✓SqrtPriceMath.getAmount0Delta 与 getAmount1Delta 的 roundUp 参数决定截断方向。池子收款必须传 true，付款必须传 false。
  • ✓流动性 1000、价格从 100 到 101 的区间中，理论代币变化量为 1000 / 10100 ≈ 0.099。
  • ✓收进时执行 divRoundingUp，商 0 余数 1000，向上进位为 1 wei；吐出时执行原生除法，商 0 截断为 0 wei。
  • ✓相同区间来回往返兑换存在严格 1 wei 的进位剪刀差，彻底防止攻击者利用舍入误差抽干池子流动性。

1. roundUp 参数的本质：池子资产永不吃亏

在 Uniswap V3 中，当价格从一个平方根价格移动到另一个平方根价格时，池子必须计算需要转移的代币数量。无论是流动性添加、移除，还是实时兑换，所有代币增量的计算最终都会汇聚到 SqrtPriceMath.sol 库中的两个核心函数：getAmount0Delta 与 getAmount1Delta。

这两个函数都带有一个关键的布尔参数：roundUp。在 UniswapV3Pool.sol 中，对该参数的赋值遵循极其严谨的安全原则：

// UniswapV3Pool.sol 兑换逻辑片段
// 池子向用户收取输入代币时（精确输出或步进输入）：
amount0 = SqrtPriceMath.getAmount0Delta(sqrtRatioTargetX96, state.sqrtPriceX96, state.liquidity, true);

// 池子向用户支付输出代币时：
amount1 = SqrtPriceMath.getAmount1Delta(state.sqrtPriceX96, sqrtRatioTargetX96, state.liquidity, false);

这一设计被称为「永远偏向池子（in favor of the pool）」：只要代币是流向池子（用户付给池子），roundUp 就必须为 true，任何不能整除的微小余数都要向上进位，迫使用户多付 1 wei；只要代币是流出池子（池子付给用户），roundUp 就必须为 false，任何多余的小数都要向下截断舍去，池子少付 1 wei。池子绝不会因为定点数计算的舍入问题多支出哪怕 1 wei 的资产。

2. 价格从 100 到 101：理论变化量 0.099

为了直观核算这种取整规则，我们构建一个极度纯粹且易于复算的整数场景。假设虚拟流动性 L = 1000，价格从平方根价格 sqrtRatioA = 100 变动到 sqrtRatioB = 101。

根据恒定乘积公式在流动性集中下的微分关系，token0 的变化量理论公式为：

Δx = L * (sqrtRatioB - sqrtRatioA) / (sqrtRatioA * sqrtRatioB)

将数值代入：

Δx = 1000 * (101 - 100) / (100 * 101) = 1000 / 10100 ≈ 0.0990099...

在实数领域，代币理论变化量不足 0.1。但在 EVM 的无符号整数世界里，代币不存在小数。这一步计算到底是变成 0 还是变成 1，完全由 roundUp 决定。

3. 收进进一要付 1，吐出舍去只给 0

现在深入 SqrtPriceMath.getAmount0Delta 源码中的分支执行流：

// SqrtPriceMath.sol
return
    roundUp
        ? UnsafeMath.divRoundingUp(
            FullMath.mulDivRoundingUp(numerator1, numerator2, sqrtRatioBX96),
            sqrtRatioAX96
        )
        : FullMath.mulDiv(numerator1, numerator2, sqrtRatioBX96) / sqrtRatioAX96;

分子 numerator1 * numerator2 为 1000。分母为 10100。

  1. 当池子收进 token0 时（roundUp = true）： 1000 除以 10100，整数商为 0，余数为 1000。由于余数大于 0，divRoundingUp 强制触发进位：0 + 1 = 1。调用者必须转入 1 wei 的 token0。
  2. 当池子吐出 token0 时（roundUp = false）： 1000 除以 10100，整数商为 0，余数 1000。原生整数除法 / 直接丢弃余数，向下截断为 0。池子转出 0 wei 的 token0。
操作方向流动性 L价格区间理论计算值roundUp 参数数学操作最终整数结算
池子收进代币 (In)1000[100, 101]0.0990099...true (进一)divRoundingUp1 wei
池子吐出代币 (Out)1000[100, 101]0.0990099...false (舍去)mulDiv / div0 wei

同样的流动性，同样的价格移动幅度，只要流向相反，结算结果就是 1 和 0 的巨大反差。这种非对称性构成了定点数数学的核心防护网。

4. 往返兑换的 1 wei 剪刀差与防抽水机制

假设一名套利者试图在同一个价格区间内反复进行往返兑换（Round-trip Swap）。他首先推动价格从 100 到 101，然后立即推动价格从 101 回到 100。

在理想的无手续费数学模型中，往返交易的总资产应该完美守恒。但在 Uniswap V3 的整数世界中：

支付 (池子收进): 1 wei
获得 (池子吐出): 0 wei
单次往返净损失: 1 wei

如果没有 roundUp 的严格不对称控制，而是错误地在收进时也向下截断，那么套利者在输入时只需付 0 wei，在输出时也能拿到 0 wei。更严重的是，一旦在另一个维度的除法中出现偏向用户的舍入漏洞，攻击者就能通过高频触发极小微步（微量兑换），在每次往返中白赚 1 wei 代币，形成著名的「舍入抽水攻击（Rounding Drain Attack）」。

正是因为 Uniswap V3 在数学底层做到了收进永远多算 1、吐出永远少给 1，使得任何试图利用舍入截断套利的交易者，每跨越一次微小区间，都在不可逆地向池子输送 1 wei 的定点数损耗。

5. 常见离线模拟器在密集微小交易中的漂移陷阱

在构建量化高频做市系统或离线链下路由回测时，许多工程师直接使用 Python 或 JavaScript 的原生浮点数模拟 SqrtPriceMath，或者统一使用整除运算符 //，完全忽略了 roundUp 布尔标志。

这种简化的模拟器在宏观大额单次兑换中误差极小，但在以下高频微小场景中会产生严重漂移：

  1. 网格做市策略（Grid Trading）：在密集 Tick 间反复高频挂单与吃单，浮点数模拟器会认为净值持续上升，而实际上链运行后由于每次穿档都承担 1-2 wei 的进位剪刀差，实际收益会显著低于回测预期；
  2. 微额套利侦测：离线机器人可能会侦测到利润只有几个 wei 的“套利机会”，但实际发起链上交易时，由于链上合约要求多付 1 wei 且少付 1 wei，导致交易无法覆盖 Gas 甚至因 1 wei 余额不足触发 IIA 回退；
  3. 储备金恒等式漂移：长周期回测若未对齐 divRoundingUp，模拟池子中的 token0 与 token1 累计储备量会脱离 L * sqrtPrice 的数学曲面。

核验一笔代币变动量时，必须严格区分是池子收款还是付款。只要是向池子注入或付款，必须核验是否执行了 divRoundingUp 并向上进一；只要是从池子提款或出款，必须核验是否截断。在流动性 1000、区间 [100, 101] 中，收进必须是 1，吐出必须是 0。

本文是分析框架。进位与舍入规则来自 SqrtPriceMath.sol 与 FullMath.sol v1.0.0。1、0 与 0.099 是严格数学推导的定点数整数结果，不构成投资建议。

6. 常见误读

为什么 SqrtPriceMath 计算代币变动时不能统一采用四舍五入？

因为四舍五入会在余数小于 0.5 时向下舍入、大于等于 0.5 时向上进位。如果池子收进代币时发生向下舍入，用户就会少付代币，导致池子储备金低于理论曲线要求；如果吐出代币时发生向上进位，池子就会多给用户代币。长期或高频套利下，攻击者只需构造特定价格微小步长，就能通过四舍五入的舍入偏离逐步抽干池子资产。

收进要付 1、吐出给 0，是不是意味着交易者永远在亏钱？

在宏观大额交易中，1 wei 的舍入差异相对于以太坊 18 位精度可以忽略不计；但在微小碎屑交易或极端区间套利中，这 1 wei 会直接决定套利是否具有实际可行性。它不仅是安全防线，更是离线套利算法与量化模拟器必须纳入计算的刚性成本。

token1 的计算是不是也有相同的进位保护？

是的。getAmount1Delta 同样接收 roundUp 参数。公式为 liquidity 乘以价格差，再除以 2^96。当 roundUp 为 true 时调用 mulDivRoundingUp 向上进一；当 roundUp 为 false 时调用 mulDiv 向下截断。池子无论对待 token0 还是 token1，均执行收进必进一、吐出必舍去的统一原则。

推广信息：精确理解 SqrtPriceMath 的进位规则是编写高精度量化合约与回测引擎的前提，而日常现货兑换的前端界面往往会将 1 wei 的定点数微小剪刀差隐去。若在研究之余需要测试小额多链资产兑换或跨链现货体验，可自行查看 Allswap 兑换。该入口仅供便捷参考，与 1 还是 0 的定点数进位推导无关，亦不构成平台背书或投资建议。请合规使用链上工具，勿用于非法用途。
