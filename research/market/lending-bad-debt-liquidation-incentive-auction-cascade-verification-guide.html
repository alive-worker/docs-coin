市场结构与流动性 / 清算核验

借贷坏账清算核验：清算奖励倒挂、DEX 流动性悬崖与拍卖级联穿仓模型

大多数 DeFi 研究者评估借贷协议安全性时，习惯盯着“超额抵押率”或“清算阈值（LT）”，认为只要 LT = 85%，资产跌去 15% 之前协议都绝对安全。这种静态视角忽略了清算套利者的真实利润约束：清算人扣押抵押物需要拿走清算奖励（Liquidation Bonus, LB）并承担 DEX 卖出滑点与 MEV 竞价成本。一旦市场深度在剧烈波动中骤降，导致卖出滑点大于清算奖励（清算奖励倒挂），或者抵押物价值跌穿 Debt × (1 + LB)，清算人就会集体停手——未实现坏账随之沉淀在池中，反向推高名义利用率与虚假存款 APY，成为高息诱捕后入存款人的隐形陷阱。

核验清单：借贷池抗穿仓与隐性坏账四步审查

  • ✓ 真实安全垫计算：读取链上 LT 与 LB，计算 Buffer = 1 - LT × (1 + LB)；若长尾抵押品真实安全垫低于 5%，在预言机偏差与区块延迟叠加下极易直接跳过健康清算区间。
  • ✓ DEX 流动性悬崖比对：统计当前价下方 5% 区间内的可清算抵押总量 Q_liq，用路由报价器测算一次性抛售 Q_liq 的滑点，核验是否满足 PriceImpact(Q_liq) < LB - 0.5%。
  • ✓ Close Factor 突增压力测试：核查协议在 HF < 0.95 或小额债务下是否解锁 100% 全额清算，评估单区块抛压翻倍后是否触发连续插针与级联清算。
  • ✓ 零抵押坏账扫描：独立枚举“抵押物余额为 0 但仍挂有债务”的地址总负债，核对其是否已被协议储备金覆盖，警惕坏账虚增利用率制造的“高 APY 幻觉”。

1. 真实安全垫公式：为什么 LT = 90% 的缓冲不是 10%

在 Aave v3、Spark、Compound v3 等主流超额抵押借贷协议中，当借款人的健康因子 HF = (Collateral × LT) / Debt < 1 时，仓位进入可清算状态。此时清算人代偿部分债务 ΔD，协议则按折扣价把价值 ΔD × (1 + LB) 的抵押物划转给清算人。

关键的数学边界在于：要让一笔清算在清零全部债务后不留下任何无担保坏账，抵押物的实时价值必须至少等于 Debt × (1 + LB)，而非 Debt。因此，从“恰好触发清算（Debt = Collateral × LT）”到“开始产生经济意义上的坏账（Collateral < Debt × (1 + LB)）”，协议真正拥有的价格抗跌缓冲为：

// 借贷市场真实抗穿仓安全垫（Effective Insolvency Buffer）
Buffer = 1 - LT × (1 + LB)

// 案例 A（主流资产 WETH）：LT = 82.5%, LB = 5.0%
Buffer_A = 1 - 0.825 × 1.05 = 13.375%   // 表观 17.5%，实际缩水 4.125%

// 案例 B（高杠杆 LST / 长尾资产）：LT = 90.0%, LB = 7.5%
Buffer_B = 1 - 0.900 × 1.075 = 3.25%    // 表观 10.0%，实际仅剩 3.25%！

这意味着在案例 B 中，只要预言机更新周期内标的瞬时跳空下跌超过 3.25%（在极端行情下几分钟即可穿透），清算人刚拿到扣押资格，抵押物就已经不够支付 Debt × 1.075。此时全额清算将直接把抵押物扣空并遗留裸露坏账；更糟的是，如果价格再跌去 4%，连 Collateral > Debt 都无法维持，外部套利者根本不会赔本出手。

2. 清算奖励倒挂与 DEX 流动性悬崖：清算人何时集体停手

即使静态账面满足 Collateral > Debt × (1 + LB)，清算能否在链上真实成交，还取决于 MEV 清算机器人的原子套利不等式：

// 原子闪电贷清算机器人盈利条件
NetProfit = ΔD × LB - Slippage(ΔC) - FlashloanFee - PriorityGasFee - BuilderTip > 0
// 等价于：必须满足 PriceImpact(ΔC) + ExecutionCost% < LB

现实中最常见的穿仓崩盘，全部源于DEX 流动性悬崖（Liquidity Cliff）与Close Factor 跳变的双重共振：

  • 集中流动性池的深度断层：在 Uniswap v3 等集中流动性池中，做市商（LP）的流动性往往高度集中在现价上下 ±3% 的窄幅区间。当第一批巨鲸仓位触发清算、把价格砸出主做市区间后，下方价格带的流动性瞬间萎缩 80% 以上，导致下一笔等量清算的滑点从 0.8% 暴增至 9%——瞬间超过 LB = 5%，形成清算奖励倒挂。
  • Aave v3 的 HF < 0.95 满额清算放大器：正常情况下 Aave v3 将 Close Factor 限制在 50%（单次最多清算一半债务），以平滑市场抛压；但一旦仓位健康因子跌破 0.95（或总债务低于 $2,000 粉尘阈值），协议自动解锁 100% Close Factor。在急跌插针时，多个大额仓位同时跨过 0.95 红线，单区块待清算抛压骤然翻倍，直接击穿 DEX 深度并把后续仓位拖入无利可图的死区。

3. 固定利差（Aave）vs 动态激励（Morpho LIF）与坏账社会化差异

不同借贷架构面对穿仓时的风险传导路径截然不同，研究时必须按协议底层机制分类核验：

  1. 固定利差模式（Aave v3 / Compound v3）：LB 由治理预先写死。优点是清算人收益确定、在深度充足时执行极快；缺点是面对极端流动性枯竭时无法自动抬高激励。若产生坏账，旧版池子不会立刻扣减存款人本金，而是将坏账滞留在账面上，等待治理动用安全模块（Safety Module）或协议收入逐步填补。
  2. 与 LLTV 绑定的清算激励因子（Morpho Blue）：Morpho Blue 根据市场的清算贷款价值比 LLTV 动态计算清算激励因子 LIF = min(1.15, 1 / (1 - 0.3 × (1 - LLTV)))。例如 LLTV = 86% 时 LIF ≈ 1.0438（奖励 4.38%），LLTV = 94.5% 时 LIF ≈ 1.0168（奖励仅 1.68%）。更关键的是，Morpho Blue 采取即时坏账社会化（Immediate Bad Debt Realization）：一旦最后一个抵押物被扣完仍剩债务，合约立刻按比例等额核销 totalBorrowAssets 与 totalSupplyAssets，亏损瞬间计入该隔离池的存款人份额净值，彻底杜绝了“先跑赢、后跑亏光”的银行挤兑（Bank Run）博弈。

4. 隐形陷阱：未实现坏账如何伪装成“高存款 APY”

对于非即时核销坏账的传统资金池（以及部分分叉自 Compound v2 / Aave v2 的中小型借贷协议），存款人最容易踩中的致命陷阱是把坏账驱动的高利率当成真实借贷需求。

假设某稳定币资金池总存款名义规模为 1,000 万 USDC，其中 300 万 USDC 属于早已穿仓、抵押物归零的僵尸坏账，另有 600 万 USDC 为正常借款，池内真实剩余现金仅 100 万 USDC。此时协议前端计算的利用率 Utilization = (600 + 300) / 1000 = 90%，刚好跨过利率模型拐点（Kink），把借款与名义存款 APY 拉升至 18%+！

如果新存款人只看仪表盘的“18% 稳定币活期收益”冲进去，实际上是在为老存款人提供退出流动性：老资金趁机把最后 100 万真金白银提走，留给后入者的则是永远无法收回的 300 万僵尸坏账凭证。因此，凡是遇到利用率长期钉死在 90% 以上、且抵押资产包含低流动性长尾代币的借贷池，必须穿透账面核查真实坏账占比。

5. 可执行链上核验规程：参数提取、深度压力测试与坏账排查

存入大额资金或撰写协议风险研报前，可直接通过 Foundry cast 与链上 Quoter 执行以下三步独立核验：

# 1. 读取 Aave v3 指定抵押资产的配置参数（提取第 3 项 liquidationThreshold 与第 4 项 liquidationBonus）
cast call 0x7B4EB56E7CD4b454BA8ff71E4518426369a138a3 \
  "getReserveConfigurationData(address)(uint256,uint256,uint256,uint256,uint256,bool,bool,bool,bool,bool)" \
  0xCollateralTokenAddress --rpc-url $ETH_RPC_URL
# 注意：Aave v3 的 liquidationBonus 以 10000 为基数（如 10500 代表 5% 奖励），计算 1 - (LT/10000)*(LB/10000)

# 2. 使用 Uniswap v3 QuoterV2 实测集中清算抛压 Q_liq 对应的真实卖出滑点
cast call 0x61fFE014bA17989E743c5F6cB21bF9697530B21e \
  "quoteExactInputSingle((address,address,uint256,uint24,uint160))(uint256,uint160,uint32,uint256)" \
  "(0xCollateral,0xUSDC,10000000000000000000000,500,0)" --rpc-url $ETH_RPC_URL
# 将返回金额除以 (Q_liq × 现货价) 得到 PriceImpact；若 PriceImpact >= LB - 0.5%，判定为高穿仓风险

# 3. 核查资金池真实可用现金（ERC20 余额）与前端展示 TotalSupply 的差额
cast call 0xUSDCAddress "balanceOf(address)(uint256)" 0xaTokenPoolAddress --rpc-url $ETH_RPC_URL

将上述链上探测固化为三条硬性风控红线：

  1. 安全垫红线：非相关性抵押资产的 1 - LT × (1 + LB) 低于 8%，或相关性资产（如 LST/ETH）低于 3% 时，必须降权配置；
  2. 深度覆盖红线：现价下方 10% 区间内全部待清算量在主流 DEX 聚合路径上的价格冲击必须严格小于 LB - 0.5%；
  3. 坏账覆盖红线：扫描链上所有 collateral == 0 && debt > 0 账户的累计坏账，若超过该池协议储备金（Reserve Factor 累计余额）的 50%，应立即停止新增存款并评估退出路径。

推广信息：在跨以太坊主网与各条 Layer 2 借贷市场比对同一抵押品的 DEX 深度悬崖、实时滑点与清算流动性缓冲时，研究者常需在不同公链间调配测试资金以验证真实路由成交价。若在市场微结构研究之余需要进行高效的多链资产调仓或跨链兑换，可参考体验 Allswap 跨链兑换。该工具仅供跨链资产调度与实测参考，与借贷协议底层清算机制无关，不构成任何投资建议；链上操作前请自行核对滑点设置、目标公链与合约授权安全。
